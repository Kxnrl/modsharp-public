Operational notes (read before relying on log completeness):

1. The native writer queue is bounded (4096 lines). When it is full, new
   lines are DROPPED and counted instead of blocking the game thread; the
   writer reports the dropped count to error.log when it catches up.
2. Managed log events at Verbose/Debug/Information/Warning level are
   buffered by asynchronous sinks. If the process terminates abnormally
   before the buffers flush, the tail of those logs can be lost. The
   Error path (managed) and the Fatal path (native) write synchronously
   to keep this window as small as possible.
3. This change was build-verified (managed: 0 warnings; native: clean link
   inside the Steam Runtime 3 "sniper" SDK container) and runtime-verified
   on one CS2 dedicated test server. This does not guarantee
   fitness for any other environment. Operators deploy at their own risk
   and are responsible for testing in their own environment.
